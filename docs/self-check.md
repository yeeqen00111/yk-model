# 自检工序（self-check）

> 每个改动（文档或代码）完成后、交付/提交前，过一遍本清单。
> 目标：让"自检"成为项目里的固定工序，而不是临场发挥。

## 1. 旧路线残留扫描（关键）

全自研路线确立后，历史措辞极易漏网。凡出现以下词，**逐一确认是"刻意保留"还是"残留"**：

- `复用`、`预编译引擎`、`只调不编`、`llama-bench`、`win-avx512`、`尚未创建`、`骨架基于`、`甜点路线`、`分层复用`、`第三人称复用`、`我们复用`
- 刻意保留允许：路线历史/决策日志存档（带 ~~删除线~~ 或"作废"标注）、外部对照的显式标注（"不属本项目 / baseline"）、证据库对第三方**事实描述**（加"参考不抄"说明）

**查法**（Git Bash）：
```bash
grep -rnE "复用|预编译|llama|bitnet|avx512|尚未|T-MAC|goTo" --include="*.md" . | grep -v ".git/"
```

## 2. 目录/文件纪律（重点防 .gitignore 误伤）

- **源码目录必须入库**：`engine/`、`train/`、`dist/`、`docs/`、`CLAUDE.md`、`.claude/`。
- gignore 只该排除：构建产物（bin/build/*.o/*.exe/*.dll）与大文件（模型/二进制）。**绝不能在 .gitignore 里出现 `engine/` 这种源码目录名**（曾因此真实丢过文件，见 c43891c 修复）。
- 验证实际跟踪：
```bash
git ls-files | grep -E "engine/|train/|dist/"   # 应非空
git status                                       # 应干净或仅预期变更
```

## 3. 交叉引用核对

- CLAUDE.md 对蓝图的引用（§0/§5/§6/§6A/§11）逐条存在。
- README 文档链接全部指向存在的文件。
- 蓝图内部：决策日志（§11）每一条都要在正文"找得到回响"；正文引用的章节号存在。

## 4. 决策与正文对齐

- 新决策 → 必须补进 §11，且正文同步改相关小节（不是只改了日志）。
- 正文与新决策冲突处 → 高亮找出（grep 决策关键词）。

## 5. 事实一致性

- 环境实测数据（dev-environment）必须反映现状：env 是否已建、git 是否已推送、工具链状态。
- 性能类数字必须带口径（benchmark-methodology §2），不自带"超带宽上限"的结论。

## 6. 提交纪律

- 提交身份用**本仓库 local**（111lw）；**不写任何 claude 署名**；不带全局配置。
- commit message 说清"改了什么 + 为什么"。

## 7. 清单模板

```
[ ] §1 旧路线残留扫描（grep 通过）
[ ] §2 git ls-files 确认源码目录已入库；无 .gitignore 误伤
[ ] §3 交叉引用核对通过
[ ] §4 决策与正文对齐
[ ] §5 事实一致性（环境实测）通过
[ ] §6 提交纪律（local 身份、无 claude、message 清晰）
```
