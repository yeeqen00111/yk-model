# 基准方法论（Benchmark Methodology）

> P0 起就用的统一口径。所有"快/慢/省"的结论必须能回溯到本文件定义的数字，否则不算数。
> 原则：**量出来之前，一切是意见；量出来之后，意见归你**。

## 1. 指标定义

| 指标 | 定义 | 测法 |
|---|---|---|
| TTFT（首 token 延迟） | 输入丢进去到第一个输出 token 出来的耗时，即 prefill 时长 | 计时 prefill 段 |
| Prefill 吞吐 | prefill 阶段 tok/s（批量并行） | prefill_tokens / TTFT |
| **Decode 吞吐** | decode 稳定段 tok/s（逐 token，唯一真正重要的用户体感） | 总输出 token 数 / 稳态耗时（剔除 prefill） |
| 峰值内存 | 加载 + 推理全过程的峰值内存占用（RSS 或任务管理器 PF） | 进程峰值 RSS；GPU 显存另记 |
| 能耗（可选） | 无独立仪表时降级为"AC/电池 + 是否风扇起飞"定性记录 | 记录设备电源状态 |
| TTFT / TPOT 分解 | 长文本下首 token 与每 token 分开报 | 分阶段计时 |

**体感换算**：单通道本机，7B Q4 顶格 ~5 tok/s → 一句话 20 字 ≈ 4s。**任何宣称用 tok/s 感知"快了"的，先对这条线。**

## 2. 测试协议（防"口径漂移"）

1. **统一 Prompt 集**（先定死，后续只能加不能改）：
   - `short`：空/极短输入，"你好" → 续写 128 token
   - `mid`：~512 token 输入 → 续写 256 token
   - `long`：~4096 token 输入 → 续写 256 token（测 KV 压力）
2. **确定性**：`--seed 42`、`-t 0`（贪心、关闭采样随机性）；上下文长度、`-ngl`、`-n_batch`、线程数全程固定并记录。
3. **流程**：冷启动 1 轮 warmup（预热缓存/页面），再正式测 **5 轮**，报**中位数 ± 极差**；剔除明显离群（>2× 中位）。
4. **环境**：测前关闭其他应用；记录 AC 还是电池（电池下必降速，数据要分开标）；记录 CPU 温度基线。
5. **版本基线**：每次测量记录 → 引擎 commit/版本、模型文件 SHA256、量化档、上下文长度。**数字永远挂在"引擎+模型+协议"三元组上。**
6. **残留检查**：模型文件的下载缓存/整页缓存导致的"第二次快"要识别——报数的必须标 warm/cold。

## 3. 快速合理性校验（self-check）

- 单通道 DDR4-3200：带宽 ≤25.6 GB/s → 任何模型的理论 decode 上限 ≈ `25.6GB/s ÷ 模型字节数`。
  - 例如 4.4GB 的 7B Q4：上限 ≈ 5.8 tok/s。**如果测出 10+，先怀疑指标错了，不是机器变强了。**
- 双通道后（如加内存）：上限翻倍，重新按上式计算。
